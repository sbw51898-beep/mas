# MAF 多智能体认知治理最小实验设计

日期：2026-07-27

## 1. 目标

从零实现一个可重复、可测试的多智能体实验骨架，使用 Microsoft Agent Framework（MAF）运行三种编排机制，并以统一格式记录讨论轨迹和基础指标。

第一版不复刻贺同学的代码，也不直接实现尚未明确的社会热力学五因子公式。它首先验证：

1. MAF 能否稳定承载独立并行、顺序圆桌和动态发言三种机制；
2. 三种机制是否产生可观察的不同讨论轨迹；
3. 实验日志和基础指标能否稳定导出并重复计算。

## 2. 范围

### 2.1 包含

- 三个具有不同角色提示词的 Agent；
- 10 道内置、带标准答案的简单选择题；
- 离线确定性假模型；
- 通过环境变量配置的 OpenAI-compatible 模型接口；
- 三种编排机制：
  - 独立并行；
  - 顺序圆桌；
  - 三因子动态发言；
- 统一 JSONL 轨迹；
- 基础指标计算；
- 自动化单元测试和最小集成测试；
- 命令行运行入口和使用说明。

### 2.2 不包含

- 贺同学原始代码或私有数据；
- 大规模数据集实验；
- 模型微调或强化学习；
- 完整社会热力学五因子公式；
- Web 界面；
- MAST、Riedl 或 Who & When 的数据导入。

这些内容只能在最小实验跑通后作为后续阶段加入。

## 3. 技术路线

采用“框架独立实验核心 + MAF 适配层”。

核心数据结构、指标、选择器和日志不依赖 MAF；MAF 只负责 Agent 调用与工作流编排。这样既可以检验 MAF，也能避免实验定义与单一框架耦合。

## 4. 数据模型

### 4.1 Question

- `question_id`
- `prompt`
- `options`
- `correct_answer`

### 4.2 AgentResponse

- `agent_id`
- `round_index`
- `answer`
- `confidence`，范围为 0 到 1
- `reasoning`
- `changed_from_previous`
- `timestamp`

### 4.3 Message

- `speaker`
- `round_index`
- `content`
- `visible_history_ids`

`visible_history_ids` 用于证明不同机制下每个 Agent 实际看到了哪些先前消息，避免只根据函数名称判断“同步”或“异步”。

### 4.4 ExperimentResult

- 实验配置；
- 题目；
- Agent 角色；
- 完整消息；
- 完整响应；
- 最终答案；
- 指标；
- 错误信息；
- 模型和框架版本。

## 5. 三种编排机制

### 5.1 独立并行 Concurrent

三个 Agent 在同一轮中只接收题目和各自角色提示，不接收本轮其他 Agent 的回答。

第一版只运行一轮。它是没有讨论影响的基线。

### 5.2 顺序圆桌 Round Robin

发言顺序固定为 A、B、C，循环三轮。每次发言者可以看到此前已经提交的全部公开消息。

它是严格的顺序机制，不称为同步机制。

### 5.3 动态发言 Dynamic

每次只选择一个 Agent 发言，并立即把消息加入公共历史。总发言次数固定为 9，与三人三轮圆桌的最大发言次数一致。

选择分数为：

```text
score =
    0.45 × disagreement
  + 0.30 × waiting
  + 0.25 × uncertainty
```

其中：

- `disagreement`：该 Agent 上次答案是否不同于当前多数答案；没有历史答案时为 1；
- `waiting`：距离该 Agent 上次发言的步数，按当前最大等待步数归一化；从未发言时为 1；
- `uncertainty`：`1 - confidence`；没有历史答案时为 1。

分数相同时按 Agent ID 排序，保证可重复。权重是第一版的工程假设，不宣称具有理论最优性；后续可替换为正式五因子公式。

## 6. Prompt 和模型接口

Agent 必须输出结构化 JSON：

```json
{
  "answer": "A",
  "confidence": 0.72,
  "reasoning": "简短理由"
}
```

模型接口由统一协议表示：

- 输入：系统提示、用户提示和可见历史；
- 输出：结构化 `AgentResponse`；
- 错误：返回明确异常，不伪造正常回答。

离线假模型根据题目 ID、Agent ID 和轮次产生确定性结果，用于测试流程，不用于研究结论。

真实模型使用 OpenAI-compatible HTTP/API 客户端。端点、模型名和密钥只从环境变量读取，不写入源码、配置样例或日志。

## 7. 指标

第一版计算：

- `accuracy`：最终答案是否正确；
- `consensus_rate`：最终一轮中占多数答案的比例；
- `wrong_consensus`：达到全体一致但答案错误；
- `flip_rate`：有前后答案的 Agent 中，答案发生变化的次数占可比较次数的比例；
- `pairwise_disagreement`：最终有效答案两两不同的比例；
- `answer_entropy`：最终答案分布的归一化香农熵；
- `speaker_share`：各 Agent 发言次数占比。

并行模式没有前后轮次，因此 `flip_rate` 明确记为 0，并在配置中标注为单轮基线。

第一版不将这些指标命名为温度、自由能或序参量。

## 8. 最终答案

- 独立并行和顺序圆桌：使用最后可用答案的多数票；
- 动态发言：使用每个 Agent 最后一次答案的多数票；
- 平票：按选项在题目中的顺序决定，确保确定性，并在日志中写入 `tie_break=true`。

## 9. 日志

每个“题目 × 编排机制”产生一条 JSONL 记录。

日志必须包括：

- 运行 ID 和随机种子；
- Python、MAF、模型和项目版本；
- 完整实验配置；
- 每个 Agent 的系统提示；
- 每次调用的用户提示；
- 可见消息 ID；
- 原始模型文本；
- 解析后的结构化回答；
- 发言选择分数；
- 最终指标；
- 异常和重试信息。

日志不得包含 API Key、Authorization Header 或完整环境变量。

## 10. 错误处理

- 模型响应不是合法 JSON：记录原始文本和解析错误，该次回答记为无效；
- 模型请求失败：按固定上限重试，并记录每次失败；
- 某 Agent 没有有效答案：从最终投票中排除；
- 所有 Agent 都无有效答案：实验标记为失败，不生成虚假最终答案；
- 单题失败不终止整个实验批次；
- 日志写入采用逐条追加，避免中途失败丢失已完成结果。

## 11. 测试策略

采用测试驱动开发。

测试至少覆盖：

1. 多数票、平票和无有效答案；
2. 共识、错误共识、翻转率、分歧率和熵；
3. 动态选择器的三个分量、权重和确定性平局处理；
4. API Key 不进入日志；
5. 并行 Agent 看不到同轮回答；
6. 圆桌后发言者能看到前面消息；
7. 动态模式的发言者由分数决定；
8. 三种模式输出相同的结果数据结构；
9. 假模型相同种子产生相同轨迹。

MAF 真实调用作为可选集成测试，默认测试套件不需要网络和 API Key。

## 12. 验收标准

第一版完成必须同时满足：

- `pytest` 全部通过；
- 不配置 API Key 也能运行 10 道题的三种模式；
- 每种模式生成 10 条有效 JSONL，共 30 条；
- 同一随机种子重复运行得到相同离线轨迹；
- 轨迹能够证明各 Agent 的实际可见历史；
- 配置 OpenAI-compatible 环境变量后，可以运行至少一道真实模型题；
- README 能让另一名同学从空环境完成安装、测试和离线运行。

真实模型运行依赖用户自行提供端点和密钥；如果当前环境没有密钥，离线验收不因此失败。

## 13. 后续阶段

最小版本验收后，按以下顺序扩展：

1. 导入 MAST 轨迹并计算相同指标；
2. 加入 Riedl 实验的协同指标；
3. 将三因子选择器替换为正式五因子公式；
4. 加入少数意见保护和强制补证等治理动作；
5. 扩大题目、模型和 Agent 数量；
6. 检验社会热力学指标是否比基础指标具有额外预测能力。
