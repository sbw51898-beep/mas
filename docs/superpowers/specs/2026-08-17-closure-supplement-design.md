# HiddenBench 闭环补充设计

## 目标

在不篡改既有冻结实验的前提下，补齐老师追问的四个问题：单智能体是否更好、错误究竟发生在披露/忽略/误解的哪一环、披露规则与继续讨论的原因是什么、人工复核如何真正落地。

## 已确认约束

- 主论文的确认性任务固定为 HiddenBench ID1、ID2、ID3；原始运行和审计已冻结。
- 当前环境只配置 DeepSeek 的 OpenAI 兼容接口，不具备可验证的 GPT-4.1 API 调用条件。
- 真人盲审必须由真实审阅者填写；模型审阅不能写成“人工金标准”。
- 新增结论必须能追溯到现有 JSONL 轨迹、消息 ID、原文引句或可重复计算的汇总脚本。

## 方案

1. 从确认性 JSONL 中重新计算并正式呈现三种同模型基线：局部信息单智能体、全信息单智能体、fixed-60 多智能体。全信息单智能体使用每次运行中独立的 `full_profile` 投票，不与局部信息投票混淆。
2. 对三个有代表性的运行建立“事实—消息—最终理由”链路卡：
   - 未披露：ID2 / fixed-60 / rep-0；
   - 正确证据被错误解释：ID2 / fixed-reveal-all / rep-1；
   - 已披露证据被后续结论覆盖或忽略：ID3 / fixed-60 / rep-0。
   每张卡保留事实、消息 ID、直接引文、最终投票与严格的结论边界。
3. 生成双人盲审包：审阅者 A、审阅者 B 的随机顺序空白表，以及一个合并计算器。计算器只在两份真人表均有效时输出一致率、AI 精确率、召回率和修订披露率。
4. 更新论文：把普通条件的自然披露规则、固定 60 次的诊断目的、单智能体对照和三张链路卡写入正文；明确 GPT-4.1+MAF / 作者模拟器+DeepSeek 是可运行的后续解耦入口而非已完成结果。

## 不做的事

- 不把模型标签、我自己的判断或未签字表格写成真人结果。
- 不把不同模型和不同框架同时变化的比较说成单因素因果结论。
- 不覆盖 2026-08-17 已交付 Word；输出新的补充版文件。
